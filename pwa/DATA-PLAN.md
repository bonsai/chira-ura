# Data Plan

No external data sources: the artifact is populated by user input and its own actions. If that changes, finalize the plan again with a `data_plan` object carrying the `markdown` body.

Design spec (not a data source): the 2026-11-13 redesign follows `~/workspace/your_files/chira-ura/ui.yaml` v0.2 (UI-01〜UI-08, phases P1–P5). P5 auto-classification is intentionally Muse-side per the spec's default reading — the app ships no built-in classifier; Muse files desk paper via the existing moveNote action.

UI-10/UI-11 (2026-11-13, same ui.yaml): elements are fixed at three places — 机 (work zone, ワーキング; default, write-first), 棚 (wiki zone, WIKI), 引き出し (drawer: hidden boxes + the trash, fixed). Boxes carry a `zone` column (`work`/`wiki`); the work shelf holds at most 8 boxes (WIKI side uncapped), enforced in createBox/setBoxHidden/setBoxZone. Commands are exactly five: 書く/探す/持ち出す/取り入れる/並び替える. Hand-written input is capped at 12 lines (imported long paper exempt). The one-time `applyLayout` action (meta `layout_version`) puts the five hand boxes （設計相談/handoverbod/サブちゃんストーリー/pwa/kaggle) on the work shelf in that order and every `wiki*` box into the wiki zone's drawer; it never touches notes, uids, or the JSONL format.

UI-12 (2026-11-13, same ui.yaml): presentation only — no schema or data change. Labels distinguish action commands from objects: commands carry a mark (✏書く / 🔍探す as emoji per the user's follow-up; ▶持ち出す / ▶取り入れる / ▶並び替える keep ▶ until emoji are decided), objects carry ▢ （▢紙 ▢箱 ▢机 ▢棚 ▢引き出し ▢ゴミ箱）. The app is a memo warehouse and a mailer — paper is both stored memo and a letter exchanged with Muse — carried by the labels themselves （手紙 chips, 交換日記）, not by prose. The box named 設計相談 is presented as the 交換日記 (its name and data untouched): a ▢交換日記 label strip at the top of its list, a ▢交換日記 sub-label in the pane, and each slip inside chipped 要望の手紙 / 結果の手紙 by chronological alternation (oldest slip = 要望, then alternating). Per the user's follow-up, the UI carries no explanatory, guidance, or supplementary text at all: only command names, object names, counts, status labels, and the paper bodies themselves.

Layout follow-ups (2026-11-13, superseding UI-10/UI-11 where they conflict): the five commands are gathered and fixed at the bottom-left of the left pane (their panels and the search field still open in the main area). Places follow the physical desk: 机の上 = the desk surface (papers being written, the write-first desk view), 机の引き出し = the working （机） zone's boxes, at most 7 visible boxes (enforced server-side in createBox/setBoxHidden/setBoxZone), 机の隣 = the trash, standing beside the desk and not part of the drawer; 棚 = the WIKI zone (external reference material for reading), its shelf holding at most 8 visible boxes (also enforced server-side). Hidden boxes are labelled 非表示の▢箱 and are uncapped. No data, uid, or JSONL change.

UI-15 (2026-11-13, ui.yaml; supersedes the naming above where they conflict): hidden boxes are managed solely by the 🔀並び替える command through an 8 SLOTS panel shown while sort mode is on — the WIKI zone's visible boxes are exactly the 8 slots (place = show on the shelf in slot order, remove = back to hidden, ↑↓ = reorder); the per-box show/hide toggle in box menus and the hidden list's individual 出す buttons are removed (hidden boxes can still be opened/read from the 非表示の▢箱 list). No schema change: slots ride on the existing hidden flag, zone, and sort order. Follow-ups the same day: (1) 📦箱を作る moved into the bottom-left action-command area; (2) all action commands are emoji-marked and ▶ is abolished everywhere (✏書く / 🔍探す / 📤持ち出す / 📥取り入れる / 🔀並び替える / 📦箱を作る； secondary actions use ✏/🗑/↩/📖); (3) movable icons (grips on ▢紙・▢箱， ⤵ drop marks on destinations) appear only while 🔀並び替える sort mode is on — drag & drop itself is therefore a sort-mode operation; (4) ▢ゴミ箱 and the unboxed-papers container are containers on the same layer as ▢箱 with fixed pane positions — reordering changes contents and assignments, never container positions; (5) all place/furniture naming is abolished in UI labels — no 引き出し / 机の隣 / 机の上 / ▢机 / ▢棚； only ▢箱， ▢箱なし， ▢ゴミ箱， and the zone names ワーキング / WIKI remain (server cap messages reworded to match). Data, uids, and the JSONL format are unchanged.

UI-20 (2026-11-13): no HR elements — every divider/rule line is removed from the UI (the dashed rule above ◼️ゴミ箱 in the object panel, the dashed rule inside each ▢紙 card, the left pane's right edge line, and the right-edge ▢すべて strip's left edge line). Sections are separated by spacing and placement only; element outlines on buttons, inputs, panels, and paper slips are not dividers and stay. No schema, data, or behavior change.

UI-18 (2026-11-13, ui.yaml; supersedes UI-13〜UI-17 caps and naming where they conflict): the UI is exactly two kinds of label — objects carry a square mark (▢ colored box / ◽️ 箱なし， the box-less paper pile / ◼️ ゴミ箱）, actions carry an emoji. Places are two: 机 (the work zone as a place name again) holds at most 8 objects — up to 6 visible colored boxes (server-enforced in createBox/setBoxHidden/setBoxZone) plus the fixed ◽️ and ◼️ — and 棚 (the wiki zone) holds everything else, uncapped; hidden boxes belong to the shelf (hidden is a state within the shelf, shown dimmed with a 非表示 label in the shelf list, no longer a separate list under the trash). Every object toggles: 🔀並び替える's manager now shows the desk's 6 slots (in = on the desk, out = hidden on the shelf) plus a 出す/しまう toggle for every shelf box. The left pane is split into two distinct panels: an object panel (places + objects, internally scrollable) and an action panel (the emoji commands, fixed at the bottom-left in its own bordered panel). The zone column, hidden flag, uids, and the JSONL format are unchanged; no data migration — the current data already satisfies the desk cap (4 visible work boxes).
