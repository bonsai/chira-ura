# 三層アーキテクチャ — 書き殴る / 醸成する（weaver）/ 選び出す（RAG）

時間軸の違う 3 つの関心を分け、**別レポ**にして**データだけで疎結合**する。
どの層も他層を `import` しない。共有するのは「フォーマット」と「置き場（パス）」だけ。

```
  人間の入力
      │
      ▼
┌──────────────────┐  生メモ（不変・追記のみ）
│ 書き殴る dump     │ ───────────────────────────┐
│ chira-ura        │                            ▼
└──────────────────┘                    ┌────────────────┐
                                        │  bonsai/wiki    │  貯めるだけ（second brain）
                                        │  raw/ (不変)     │
                                        └────────────────┘
                                                 │ 読む
                                                 ▼
                                        ┌────────────────┐
                                        │ weaver（織姫）  │  再構成・再生成 + メタデータ
                                        │ agent           │
                                        └────────────────┘
                                                 │ ripe/ + メタデータ
                                                 ▼
                                        ┌────────────────┐
                                        │ rag             │  読み出す・呼び出せる
                                        └────────────────┘
                                                 │
                                                 ▼
                                           人間 / Muse
```

## m / v / c
- **m = `wiki`, `weaver`** — 蓄積（wiki）と、それを醸成する agent（weaver）
- **v = `rag`, `llm`** — 検索（rag）と生成（llm）
- **c = `mcp`, `cli`** — 呼び出し口（MCP サーバ / CLI）

## 各層

### 1. 書き殴る層（dump）— `bonsai/chira-ura`
- **役割**: 思いつきを最速で吐き出す。整理しない。捨てない。
- **代表**: crx / cli（`chira`）/ gui/win（`chira.exe`）/ gui/rust / mobile（計画）。
- **出力**: タイムスタンプ付きの生メモ（不変）→ `bonsai/wiki` の `raw/<MM>/<ts>_<id>.txt`。
- **性質**: オフライン優先・即保存・冪等。**速さが全て**。

### 2. 基盤 — `bonsai/wiki`
- **役割**: **貯めるだけ**。生メモの不変ストア（second brain）。
- 解釈・整理はしない。置くだけ。

### 3. 醸成する層（weaver / 織姫）— `bonsai/weaver`
- **役割**: agent が生メモを素材に、**再構成・再生成**して**創造的な作品**を織り上げ、**メタデータ**を付ける。
- **入力**: `wiki/raw/`（生メモ・不変）。
- **出力**: `wiki/ripe/<YYYY>/<slug>` + メタデータ（frontmatter / `meta.json`）。
- **性質**: 非同期・バッチ・低頻度。急がない。**生には書き戻さない**。
- 連結・分類・重複排除・関連付け（メタデータ）も行うが、それは RAG の下地であって目的ではない。

#### 出力はクリエイティブに（LLM-wiki を超える）
weaver の output は、無味な要約／百科事典的な wiki ページ**ではない**。
生メモという素材から、**読んで面白い・心が動く形**へ再構成・再生成する。

- 形（例）: 物語 / ショートショート / 詩 / 歌詞 / 対話・戯曲 / エッセイ・コラム / 手紙 / 新聞・雑誌風 / 図解 / 語り（音声）…
- 素材への参照（トレーサビリティ）とメタデータは必ず付ける（創作でも出典は残す）。
- トーン・視点・構成は素材と文脈から選ぶ。**ただの箇条書きにしない**。
- 同じ素材から複数の解釈・複数の作品を許す（正解はひとつではない）。
- ねらい: あとで読み返したときに「発見」と「再訪の喜び」があること。
- **お手本**: `bonsai/weaver` の `examples/`（生メモ → 随筆の実例、frontmatter 付き）。

### 4. 選び出す層（rag）— `bonsai/rag`
- **役割**: 醸成済み＋メタデータを **RAG** にして、**読み出す・呼び出せる**ようにする。
- **入力**: `wiki/ripe/`。
- **出力**: 回答 / 推薦 / digest（書き戻しは `wiki/pick/`）。MCP / API として呼べる形（pi / Muse から）。
- **性質**: 読み取りが主。**選ぶ、作らない**。

## 疎結合のルール
1. **レポ独立**: 各層は独立リポジトリ。他層のコードを参照しない（サブモジュール・パッケージ依存も無し）。
2. **契約はデータだけ**: 受け渡しはファイル or HTTP。フォーマット（メモ JSON `{id,title,content,updatedAt}` / `.txt` / frontmatter）と置き場（`wiki` のパス）で契約。
3. **追記のみ・不変**: 生メモは書き換えない。各層は自分の出力領域にのみ書く。
4. **冪等・耐障害**: どの層が落ちても他層は止まらない。未処理は次回リトライ。
5. **スキーマは共有、コードは非共有**: スキーマ/パスは文書で合意（本 doc）。

## 置き場
```
bonsai/wiki
├── raw/<MM>/<ts>_<id>.txt     # 書き殴る層の出力（不変）
├── ripe/<YYYY>/<topic>.md     # weaver の出力 + メタデータ
└── pick/<YYYY-MM-DD>.md       # rag の出力（選別・digest）
```

## レポ対応
| 層 | リポジトリ | 状態 |
|---|---|---|
| 書き殴る dump | `bonsai/chira-ura` | **実装済み** |
| 基盤 | `bonsai/wiki` | second brain（`raw/` の受け皿） |
| 醸成 weaver | `bonsai/weaver` | **新規（README のみ）** |
| 選び出し rag | `bonsai/rag` | **新規（README のみ）** |
| 提示 Muse | `bonsai/Muse-Chat-MCP` | 既存 |

## 非目標
- 層をまたぐ同期呼び出し（遅い層が速い層を止めない）。
- 生メモのその場での整理（dump は捨てない・急がない、weaver に任せる）。
