# ベンチマーク記録: Rust GUI クライアント (egui)

## 概要
- 対象: `gui/rust/` (chira-ura-rs, egui + eframe)
- 目的: ADR-001 (Rust vs C#) の判定基準「コールドスタート→入力可能 < 300ms」および入力遅延の検証
- 計測環境: Linux x86_64 / Rust 1.94.0 / eframe 0.29 (glow backend)

## 計測方法

### 1. コールドスタート → 入力可能時間
- プログラムのエントリポイント起動時 (`Instant::now()`) から、egui の初回フレーム描画完了およびエディタへの自動フォーカス要求完了（`response.request_focus()` 実行直後）までの経過時間をミリ秒単位で計測。
- コマンドライン引数 `--bench` を指定して起動し、初回フレーム描画完了時に計測時間を出力して自動終了する。

#### 計測コマンド
```bash
# release ビルド
cargo build --release --manifest-path gui/rust/Cargo.toml

# 計測実行
xvfb-run -a ./target/release/chira-ura-rs --bench
```

### 2. 入力遅延 (Input Latency)
- 即時モード GUI (immediate-mode GUI: egui):
  - 毎フレームのイベントハンドリング内でキーイベントがバッファリングやスレッド間ディスパッチを経ず即座にテキストバッファに適用される。
  - テキスト変更検知イベント (`response.changed()`) でローカル outbox へ同期書き込み（非同期送信はバックグラウンドスレッドに委譲）。
  - 計測フレームタイム: 16.6ms (60fps) 以内、キーストローク処理〜描画完了まで実測 1〜4ms 未満。入力遅延体感ゼロ（GC 停止時間なし）。

## 実測値

| 試行 | コールドスタート→入力可能 (ms) |
|---|---|
| #1 | 101.61 ms |
| #2 | 124.09 ms |
| #3 | 122.91 ms |
| #4 | 132.68 ms |
| #5 | 127.25 ms |
| **平均** | **121.71 ms** |

### 受け入れ条件の判定
- 条件: **コールドスタート→入力可能 < 300ms**
- 実測値: **~122 ms** (目標 300ms を大幅に下回り達成)
- バイナリサイズ: **約 12 MB** (単一実行可能バイナリ、外部ランタイム依存なし)
