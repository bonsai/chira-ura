# ADR-001: Windows クライアントの実装言語 — Rust vs C#

- 状態: **Accepted（C# / .NET 採用）** — 2026-11-05 決定
- 対象: bonsai/chira-ura Issue #12「Windowsクライアント：付箋メモ専用アプリ」
- 前提: 思想は「DBはひとつ（正は bonsai/wiki の raw/）、UI/クライアントは多様に」。本 ADR は入口の1つの実装言語だけを決める

## 背景

ユーザーの第一要件は **「爆速のメモ帳」**：
- コールドスタートから入力可能までの時間が短いこと
- キー入力の遅延が感じられないこと
- 保存が速いこと（既存リズム：FE API へ送ってキャッシュ止まり、時間毎バッチで wiki/raw へ）

機能は付箋メモのみ。整理・検索・読み戻しは足さない（後段はチャット/Muse 側）。

## 比較

| 観点 | Rust | C# / .NET |
|---|---|---|
| コールドスタート | ◎ ネイティブ単一バイナリ。GUI を軽く（egui / windows-rs の素の Win32）すれば最速級 | ○ NativeAOT を使えば速い。通常の WPF/WinUI はランタイム＋フレームワーク分重くなりやすい（WinForms＋AOT なら実用圏） |
| 入力遅延 | ◎ 描画ループを自分で持てる。GC なし | ○ 実用上は問題ないが GC の影響をゼロにはできない |
| バイナリ／配布 | ◎ 数 MB の単一 exe、ランタイム不要 | △ AOT でも大きめ。通常配布は .NET ランタイム前提になりがち |
| Windows 連携（常駐・ホットキー・トレイ等） | ○ windows-rs で可能だが手数は多い | ◎ 標準の流儀が揃っていて速い |
| 開発速度 | △ 所有権・借用の学習コスト。UI の作り込みは地道 | ◎ フォームを置けばすぐ動く。実装担当（ローカル CLI / Jules）の生産性は高い |
| 非同期同期（FE API 送信・outbox） | ○ reqwest / rusqlite で十分 | ◎ HttpClient / Microsoft.Data.Sqlite が標準で揃う |
| 生態系との整合 | △ bonsai 内に Rust 実績はほぼ無い。新規の型 | ○ Windows アプリの本命言語。TOY（Windows）中心の運用に合う |
| 保守 | △ 書ける人が限られる | ○ 読み手が多い |

## 論点の要約

- **速度だけ**で切れば Rust が勝つ。特に「常駐させず、叩いたら即開いて即書ける」体験はネイティブ単一バイナリが強い
- **作る速さと保守**で切れば C# が勝つ。付箋メモ程度の UI なら C# + WinForms + NativeAOT でも「爆速」の実用ライン（起動数百 ms 級）は狙える
- どちらでも、同期先（FE API）と保存形式（メモ JSON）は既存契約のまま変えない

## 推奨（提案）

**第一候補：Rust**（要件の芯が速度であり、配布も単一 exe で一番軽いため）
**対案：C# + WinForms + NativeAOT**（実装速度と保守を優先する場合。WPF/WinUI は起動速度の観点で避ける）

判定は実測で決める：両方で「起動→入力可能」の最小プロトタイプを測り、差が体感できないなら開発速度の C# を取る。

## 決定

**C# / .NET（WinForms）を採用。**
不採用（Rust）の理由: Windows 上での最速立ち上げ・保守性と、TOY 環境（Windows 中心運用）における標準 .NET エコシステムとの親和性を優先。付箋メモ程度の軽量 UI では C# / WinForms で十分な起動速度が得られるため。

## 影響

- 決まった言語で bonsai/chira-ura に Windows クライアントの実装 Issue を切る（実装はローカル CLI / Jules）
- 既存の crx / CLI / API / MCP には影響しない（入口が1つ増えるだけ）
